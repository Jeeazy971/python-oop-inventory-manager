# 17.1 — Pourquoi la POO existe

## Le problème

Sans POO, les données et les fonctions sont séparées.
Les dicts regroupent les données mais n'ont pas de comportements.
Rien ne protège l'intégrité des données.

## Ce que la POO apporte

- **Encapsulation** : données + comportements au même endroit
- **Réutilisabilité** : un moule (classe), autant d'instances qu'on veut
- **Modélisation** : le code parle le même langage que le domaine métier

## Classe vs objet

- La **classe** est le plan (écrit une fois dans le code)
- L'**objet** est l'instance (créé à l'exécution, en mémoire)
- Chaque objet a ses propres données, mais partage les méthodes de la classe

## Pourquoi le dict ne suffit pas

1. Aucune validation des données (qty = -50 passe sans erreur)
2. Fonctions éparpillées, aucun lien formel avec les données
3. Pas de typage → pas d'autocomplétion, pas de détection d'erreur
4. Pas d'identité → `isinstance()` ne fonctionne pas, héritage impossible
5. Tout est exposé, aucune interface publique/privée

## Classe ou fonction ?

| Situation | Quoi utiliser |
|---|---|
| État qui évolue + comportements | Classe |
| Plusieurs instances du même type | Classe |
| Transformation simple, pas d'état | Fonction |
| Une seule méthode, aucun état | Fonction (pas une classe) |

> Règle : *"Est-ce que j'ai besoin de mémoriser quelque chose entre deux appels ?"*
> Si non → fonction. Si oui → classe.

## À retenir

Une classe = une responsabilité (je verrai SOLID plus tard, après l'héritage).
Ne pas créer une classe juste pour regrouper des fonctions utilitaires → c'est un module.
(regarder les fichiers html en exemples)
